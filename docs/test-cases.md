## 1. 개요

본 문서는 학원용 문제 제출기 시스템의 **상세 테스트 케이스**를 정의한다.  
각 케이스는 TC-ID, 유형, 우선순위, 전제조건, 단계, 기대결과, REQ/US 매핑, 구현용 메모를 포함하며, **테스트 코드 작성 시 직접 참조**할 수 있도록 구성한다.

### 1.1 식별 규칙

- **TC-ID**: `TC-{영역}-{연번}` (예: TC-AUTH-001)
- **유형**: Unit | Integration | API | E2E | Security | Performance
- **우선순위**: P0(필수) | P1(중요) | P2(선택)
- **매핑**: REQ-XXX, US-XXX, TS-XXX(시나리오 ID)

### 1.2 문서 구조

- **2. 인증·권한** (TC-AUTH-*)
- **3. 파일 업로드** (TC-UPLOAD-*)
- **4. 추출 작업** (TC-EXTRACT-*)
- **5. 자동 태깅** (TC-TAG-*)
- **6. 검수** (TC-REVIEW-*)
- **7. 문항 검색** (TC-SEARCH-*)
- **8. 시험지 제작** (TC-EXAM-*)
- **9. 데이터·감사·저작권** (TC-DATA-*)
- **10. 비기능** (TC-NFR-*)
- **11. 기존 추출 스크립트** (TC-LEGACY-*)

## 2. 인증·권한 (TC-AUTH)

### TC-AUTH-001: 정상 로그인 시 액세스 토큰 발급

| 항목 | 내용 |
|------|------|
| **유형** | API |
| **우선순위** | P0 |
| **매핑** | REQ-054, REQ-055, US-023, TS-AUTH-001 |
| **전제조건** | 사용자(이메일/비밀번호)가 DB에 존재하고 is_active=true |
| **단계** | 1. `POST /api/v1/auth/login`에 `email`, `password` 전달<br>2. 응답 본문·헤더 확인 |
| **기대결과** | HTTP 200, `access_token`(또는 동등) 반환, 만료 시간 정보 포함. 이후 인가 헤더에 해당 토큰 사용 시 200 반환 |
| **구현 메모** | pytest + httpx 또는 requests. Fixture로 테스트 사용자 생성. JWT decode하여 exp 검증 가능 |
