이 이미지는 국어 수능 문제집의 한 페이지이다.
이 이미지에서 **각 문제(문항) 영역만 잘라서 개별 이미지로 저장하는 파이썬 스크립트**를 작성할 예정이다.
**OpenCV, scikit-image, NumPy, PIL 등 이미지 프로세싱 라이브러리만 사용**하며, **OCR·LLM·텍스트 인식은 사용하지 않는다.**
따라서 **선(가로/세로), 테두리(사각형), 색/밝기, 여백·간격, 픽셀 블록** 등,  
**Hough 변환, 엣지 검출, morphological 연산, contour, threshold** 같은 기법으로 탐지 가능한 정보만 문장으로 서술해 달라.

---

### 1. 탐지 가능한 가로선

- **위치와 개수**
  - 페이지를 위에서 아래로 scan할 때, **연속된 가로선**이 몇 개 있고, 각각 **대략 어느 y 구간**(상·중·하)에 있는지.
- **역할**
  - **헤더 하단**을 나누는 가로선: 첫 번째 긴 가로선인지, 두께·색(검정/회색).
  - **푸터 상단**을 나누는 가로선: 유무, 두께·색.
  - **문제와 문제 사이**에 가로 구분선이 있는지. 있다면 두께·연속성(페이지 폭 전체인지, 단 폭만인지).
- **선의 특징**
  - 실선인지, 점선인지(점선이면 line detection이 어려울 수 있음).
  - **대략적인 두께(픽셀)** 또는 “얇은 실선/두꺼운 실선” 정도.
  - 배경 대비: 검정 선이 흰 배경 위인지 → **밝기 차이로 threshold·Canny 후 Hough 등으로 검출 가능한지**.

→ 이 정보로 **헤더/본문/푸터의 y 경계**를, 그리고 가능하면 **문제 구간의 상·하**를 선 단위로 나눌 수 있음.

---

### 2. 탐지 가능한 세로선

- **위치와 개수**
  - **단(column) 구분 세로선**이 몇 개인지, **대략적인 x 위치**(페이지 폭의 비율, 예: 중앙 50% 근처).
- **선의 특징**
  - 두께, 실선/점선, 색, **헤더 구간을 지나는지·본문만 있는지**.
  - 위에서 아래로 **어디까지 이어지는지**(헤더 아래~푸터 위 전체인지, 중간에 끊기는지).
- **여러 단이 있을 때**
  - 2단이면 세로선 1개, 3단이면 2개 등.  
  - 각 세로선 **왼쪽/오른쪽**이 각각 하나의 “열(column)”이 되며, **한 열 안에 여러 문제가 세로로 쌓임**.

→ 이 정보로 **좌·우 경계(열 단위)**를 정하고, **한 문제의 x_min, x_max = 해당 열의 좌·우**(세로선 포함 여부는 2번에서 명시).

---

### 3. 탐지 가능한 사각형(테두리) — contour 후보

- **〈보기〉, 〈학습 활동〉 등 박스**
  - **형태**: 사각형 테두리(실선/점선), 대략적인 두께.
  - **색**: 검정/회색, 배경과의 대비.
- **contour로 잡을 수 있는지**
  - **닫힌 사각형**인지(한 바퀴 이어지는지), 모서리가 직각인지.
  - **다른 선·문자와 겹치거나 붙어 있는지** → 붙어 있으면 한 contour로 같이 잡힐 수 있음.
- **위치**
  - 박스가 **한 문제의 질문 위/아래/중간** 어디에 있는지(상대적 위치).
  - 박스가 **세로로 어느 정도 높이**를 차지하는지(한 문제 높이의 대략 몇 %).

→ **사각형 contour**를 찾아서, 그 **bounding box**로 “이 블록은 한 문제의 부속(보기/학습활동)”으로 묶고, **문제의 y_max를 박스 아래로 확장**하는 데 사용.

### 4. 색·밝기로 구분되는 영역 — threshold용

- **헤더의 진한(검정) 영역**
  - “홀수형” 등이 들어 있는 **검정(또는 진한 회색) 직사각형**이 있는지.
  - **위치·크기**: 헤더의 왼쪽/오른쪽, 세로·가로 범위.
  - **grayscale threshold** 또는 **색 채널 threshold**로 “헤더 제거용 마스크”를 만들 수 있는지.
- **본문**
  - 대부분 **흰 배경 + 검정 글자**인지, 배경에 약한 회색/크리프 등이 있는지.
- **푸터**
  - 헤더처럼 **진한 블록**이 있는지, 아니면 **글자만** 있고 배경은 흰지.

→ **헤더/푸터를 마스킹해 제외**하거나, **“문제 후보 영역”을 밝기 기준으로 한정**하는 데 사용.

---

### 5. 문제 간 구분 — 간격·블록 (OCR/LLM 없이)

- **문제와 문제 사이의 세로 간격**
  - 한 문제 **내부**의 “줄과 줄 사이”보다, **문제와 문제 사이**가 **두드러지게 큰지** (예: 2배 이상).
  - 그 큰 간격이 **거의 항상 존재하는지**, 일부 문제 쌍에서만 있는지.
- **가로선·박스 없이 구분할 때**
  - **세로 흑백 투영(vertical projection)** 또는 **수평으로 긴 빈 줄(white band)**이 “문제 사이”에 반복되는지.
  - **morphology(닫기/열기)**로 글자 줄을 블록으로 묶었을 때, **블록과 블록 사이의 y 간격**으로 “새 문제 시작”을 나눌 수 있는지.
- **한 문제 내부**
  - 질문 + ①~⑤ 보기 + (있는 경우) 〈보기〉·〈학습 활동〉·표가 **연속된 블록**으로 붙어 있고,  
    **다음 문제와는 위에서 말한 “큰 간격”**으로 떨어져 있는지.
- **예외**
  - 〈보기〉 박스가 **문제와 다음 문제 사이**에 걸쳐 있거나,  
    **다음 문제 번호와 가깝게** 붙어 있는 경우가 있는지.  
  - 그런 경우 **간격만**으로는 나누기 어려우므로, **박스 contour**나 **가로선**을 보조로 써야 함.

→ **“큰 세로 간격”을 threshold로 두고**, **간격 사이를 한 블록(한 문제)으로** 묶는 휴리스틱을 설계할 수 있음.  
  (문제 번호·보기 번호는 읽지 않고, **기하학적 구간**만 사용.)

### 6. 비율·고정 패턴 (해상도 독립에 유리)

- **고정 비율이 있다면**
  - 헤더 높이가 **페이지 높이의 대략 몇 %**인지.
  - 푸터 높이, **단 구분 세로선의 x 위치**(예: 폭의 50%).
  - **본문(헤더 아래~푸터 위)이 페이지 높이의 대략 몇 %**인지.
- **한 문제의 대략적 높이**
  - 짧은 문항은 **본문 영역 높이의 몇 %**, 긴 문항(〈보기〉·표 포함)은 **몇 %** 정도인지.  
    (정확한 숫자보다 “짧은 편/긴 편” 비율.)
- **스캔/해상도**
  - 실제 사용할 이미지가 **스캔(해상도·DPI)**인지, **스크린 캡처**인지.  
  - 선 두께·간격이 **해상도에 따라 픽셀 값이 달라질 수 있음** → **비율·상대적 크기**가 더 안정적일 수 있음.

→ **픽셀 절대값 대신 비율**로 허용 범위를 두면, DPI가 달라도 같은 파이프라인을 쓸 수 있음.

### 7. 추출 알고리즘 설계용 — 권장 탐지 순서

- **1단계: 헤더·푸터 제거**
  - **가로선**으로 상·하를 자르는 게 좋은지,  
    아니면 **헤더/푸터의 진한 영역(threshold)** 또는 **고정 비율(예: 상단 5%, 하단 5%)**로 자르는 게 좋은지.
- **2단계: 열(column) 나누기**
  - **세로선**만으로 2단을 나눌 수 있는지,  
    세로선이 불완전하면 **세로 투영(column-wise)**에서 “빈 구간”으로 열 경계를 보완할 수 있는지.
- **3단계: 한 열 안에서 문제 구간 나누기**
  - **우선**: “문제 사이의 큰 세로 간격” + (있는 경우) “문제 사이의 가로선”.
  - **보조**: 〈보기〉·〈학습 활동〉 **사각형 contour**를 찾아, 그 **아래쪽**까지를 한 문제로 묶기.
- **4단계: 문제가 두 열에 걸친 경우**
  - 그런 레이아웃이 **있는지/없는지**.  
  - 있다면: **왼쪽 열의 마지막 블록**과 **오른쪽 열의 첫 블록**을 **y 정렬(겹치는 구간)**로 이어 붙일 수 있는지.

→ 위 순서를 **문장으로 써 두면**,  
  `가로선 검출 → threshold(헤더/푸터) → 세로선 검출(다단) → 간격/contour(문제 분할)` 같은 **OpenCV 파이프라인**을 그대로 설계할 수 있음.

### 8. OpenCV/이미지 프로세싱에서 쓰지 않을 것

- **텍스트 의미**: “19.”, “20.”, “①”, “②” 등의 **숫자·기호를 인식하여** 구분하는 방법.
- **OCR(예: Tesseract) 또는 LLM**을 전제로 한 레이아웃 분석.
- **자연어**로 “질문”과 “보기”를 구분하는 설명.

→ 위와 같은 내용은 **서술하지 말고**,  
  **선, 사각형, 색, 밝기, 간격, 블록**만으로 구분 가능한 부분 위주로 써 주세요.
