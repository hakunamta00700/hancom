- 본 문서의 요구사항은 기본적으로 **MVP 범위**를 의미합니다.

## 1. 기능 요구사항

### 1.1 콘텐츠 수집 및 관리

#### 1.1.1 파일 업로드
- **REQ-001**: 시스템은 PDF, 이미지 파일(PNG, JPG)을 업로드할 수 있어야 한다.
- **REQ-001-A [로드맵]**: 시스템은 HWP 파일을 업로드할 수 있어야 한다. *(Windows/한컴 종속)*
- **REQ-002**: 단일 파일 또는 다중 파일 업로드를 지원해야 한다.
- **REQ-003**: 업로드 파일 크기 제한: PDF/이미지 50MB
- **REQ-003-A [로드맵]**: 업로드 파일 크기 제한: HWP 20MB
- **REQ-004**: 업로드 시 소스 문서 메타데이터 입력 (제목, 출처, 저작권 정보, 출제시기)
- **REQ-005**: 업로드 진행률 표시 (프로그레스 바)

#### 1.1.2 문항 추출
- **REQ-006**: PDF 파일을 이미지로 변환 (PyMuPDF 사용, DPI 150 기본값)
- **REQ-007**: 이미지에서 레이아웃 분석 (헤더/푸터/단 분할, OpenCV 기반)
- **REQ-008**: OCR을 사용하여 문항 번호 감지 (EasyOCR, 한국어/영어 지원)
- **REQ-009**: 문항 영역을 크롭하여 개별 이미지로 저장
- **REQ-010**: OCR을 사용하여 문항 텍스트 추출 (지문, 문제, 선택지)
- **REQ-011**: 추출 실패 시 재시도 옵션 제공
- **REQ-012**: 추출 작업은 비동기로 처리 (작업 큐 사용)

#### 1.1.3 자동 태깅
- **REQ-013**: LLM을 사용하여 문항의 과목 자동 추정
- **REQ-014**: LLM을 사용하여 문항의 단원 자동 추정
- **REQ-015**: LLM을 사용하여 문항의 유형 자동 분류 (객관식, 서술형, 지문형 등)
- **REQ-016**: LLM을 사용하여 문항의 난이도 자동 추정 (1~5 스케일 또는 Easy/Medium/Hard)
- **REQ-017**: 자동 태깅 결과에 신뢰도 점수 표시
- **REQ-018**: 프롬프트 버전 관리 (태깅 품질 추적)

#### 1.1.4 검수 워크플로우
- **REQ-019**: 검수 대기 중인 문항 목록 표시
- **REQ-020**: 검수 화면에서 원문 이미지, 크롭 이미지, 추출 텍스트를 동시에 확인 가능
- **REQ-021**: 추출된 텍스트 수정 가능 (직접 편집)
- **REQ-022**: 자동 태깅 결과 수정 가능 (과목, 단원, 유형, 난이도)
- **REQ-023**: 메타데이터 입력 폼 (출제시기, 저작권 정보 등)
- **REQ-024**: 검수 액션: 승인, 반려, 수정 후 재제출
- **REQ-025**: 검수 이력 기록 (누가, 언제, 무엇을 수정했는지)
- **REQ-026**: 검수 완료율 대시보드 (전체 대비 검수 완료 비율)

### 1.2 문항 검색 및 필터링

#### 1.2.1 검색 기능
- **REQ-027**: 다중 조건 검색 지원 (과목, 단원, 유형, 난이도, 출제시기, 키워드)
- **REQ-028**: 키워드 검색은 지문, 문제, 선택지 텍스트를 대상으로 수행
- **REQ-029**: 검색 조건 저장 및 재사용 (즐겨찾기)
- **REQ-030**: 검색 결과 정렬 옵션 (최신순, 난이도순, 출제시기순, 관련도순)
- **REQ-031**: 검색 결과 페이지네이션 (페이지당 20개 기본값)

#### 1.2.2 검색 결과 표시
- **REQ-032**: 검색 결과에 문항 썸네일 이미지 표시
- **REQ-033**: 검색 결과에 문항 제목/지문 일부 표시 (최대 200자)
- **REQ-034**: 검색 결과에 태그 표시 (과목, 단원, 유형, 난이도)
- **REQ-035**: 문항 상세 정보 모달/페이지 (전체 텍스트, 이미지, 메타데이터)

### 1.3 시험지 제작

#### 1.3.1 조건 설정
- **REQ-036**: 시험지 조건 설정 폼 (과목, 단원, 유형, 난이도 범위, 총 문제 수)
- **REQ-037**: 난이도 분포 설정 (쉬움/보통/어려움 비율)
- **REQ-038**: 조건에 맞는 문항 자동 추천
- **REQ-039**: 추천 문항 수가 부족한 경우 알림 표시

#### 1.3.2 문항 선택
- **REQ-040**: 검색 결과에서 문항 선택 (체크박스 또는 드래그 앤 드롭)
- **REQ-041**: 선택된 문항 목록 표시 (선택 순서 표시)
- **REQ-042**: 선택된 문항 제거 기능
- **REQ-043**: 중복 방지 (이미 선택된 문항은 검색 결과에서 제외 표시)
- **REQ-044**: 문항 순서 변경 (드래그 앤 드롭)

#### 1.3.3 시험지 미리보기
- **REQ-045**: 시험지 미리보기 화면 (문항 목록, 번호, 내용)
- **REQ-046**: 난이도 분포 차트 표시 (파이 차트 또는 바 차트)
- **REQ-047**: 총 문제 수, 예상 소요 시간 표시
- **REQ-048**: 미리보기에서 문항 추가/제거 가능

#### 1.3.4 시험지 내보내기
- **REQ-049**: PDF 형식으로 시험지 생성 및 다운로드
- **REQ-050**: PDF 레이아웃 설정 (페이지 크기, 여백, 폰트)
- **REQ-051 [로드맵]**: HWP 형식으로 시험지 생성 (Windows 전용, 옵션)
- **REQ-052**: 시험지 템플릿 선택 (기본 템플릿, 커스텀 템플릿)
- **REQ-053**: 생성된 시험지 저장 (이력 관리)

### 1.4 권한 및 보안

#### 1.4.1 사용자 인증
- **REQ-054**: 이메일/비밀번호 기반 로그인
- **REQ-055**: 인증 토큰 만료 정책 적용 (예: 액세스 토큰 30분 만료) 및 재인증/리프레시 정책 제공
- **REQ-056**: 비밀번호 재설정 기능

#### 1.4.2 역할 기반 접근 제어 (RBAC)
- **REQ-057**: 역할 정의: 시스템 관리자, 운영자, 교사, 학생
- **REQ-058**: 시스템 관리자: 모든 기능 접근 가능
- **REQ-059**: 운영자: 콘텐츠 업로드, 검수, DB 관리
- **REQ-060**: 교사: 문항 검색, 시험지 제작, 배포
- **REQ-061**: 학생: 시험지 풀이, 결과 확인 (MVP에서는 최소 기능)

#### 1.4.3 조직(학원) 단위 데이터 격리
- **REQ-062**: 조직(학원) 단위로 데이터 격리
- **REQ-063**: 조직 관리자: 해당 조직 내 사용자 관리
- **REQ-064**: 조직별 문항 DB 분리 (선택적 공유 가능)

#### 1.4.4 감사 로그
- **REQ-065**: 모든 중요 작업 기록 (업로드, 검수, 시험지 생성, 삭제 등)
- **REQ-066**: 감사 로그 항목: 사용자, 시간, 작업 유형, 대상, 결과
- **REQ-067**: 감사 로그 조회 및 필터링 (관리자 전용)
- **REQ-068**: 감사 로그 보관 기간: 1년

### 1.5 저작권 및 출처 관리

#### 1.5.1 저작권 정보
- **REQ-069**: 출처 정보 필수 입력 (저작권자, 출판사, 출제기관 등)
- **REQ-070**: 라이선스 정보 입력 (사용 범위, 재배포 허용 여부)
- **REQ-071**: 저작권 정보는 시험지 생성 시 포함 (PDF 하단)
- **REQ-072**: 저작권 위반 신고 기능

#### 1.5.2 출처 추적
- **REQ-073**: 문항별 출처 정보 표시
- **REQ-074**: 소스 문서와 문항 간 연결 유지
- **REQ-075**: 출처 정보 수정 이력 기록

## 2. 데이터 요구사항

### 2.1 데이터 모델
- **REQ-076**: 문항(Problem) 엔티티: ID, 이미지, 텍스트, 메타데이터
- **REQ-077**: 지문(Passage) 엔티티: 문항과 연결된 읽기 자료
- **REQ-078**: 선택지(Choice) 엔티티: 객관식 문항의 보기
- **REQ-079**: 태그(Tag) 엔티티: 과목, 단원, 유형, 난이도 등
- **REQ-080**: 시험지(ExamPaper) 엔티티: 문항 목록, 메타데이터
- **REQ-081**: 소스 문서(SourceDocument) 엔티티: 원본 파일 정보
- **REQ-082**: 검수 작업(ReviewTask) 엔티티: 검수 상태, 이력
- **REQ-083**: 사용자(User) 엔티티: 인증 정보, 역할, 조직
- **REQ-084**: 감사 로그(AuditLog) 엔티티: 작업 기록

자세한 스키마는 [데이터 모델 문서](data-model.md) 참조.

### 2.2 데이터 무결성
- **REQ-085**: 외래키 제약 조건으로 데이터 무결성 보장
- **REQ-086**: 소프트 삭제 (삭제된 데이터는 표시만 하지 않음)
- **REQ-087**: 데이터 백업: 일일 자동 백업
- **REQ-088**: 데이터 복구: 백업에서 복구 가능

### 2.3 데이터 보존 및 삭제
- **REQ-089**: 사용자 요청 시 데이터 즉시 삭제 (GDPR 준수)
- **REQ-090**: 삭제 요청 이력 기록
- **REQ-091**: 감사 로그는 1년 보관 후 자동 삭제

## 3. 운영 요구사항

### 3.1 작업 큐 관리
- **REQ-092**: 문항 추출 작업은 비동기 큐로 처리 (Celery/RQ)
- **REQ-093**: 작업 상태 표시 (대기 중, 처리 중, 완료, 실패)
- **REQ-094**: 작업 실패 시 재시도 메커니즘 (최대 3회)
- **REQ-095**: 작업 큐 모니터링 대시보드

### 3.2 파일 스토리지
- **REQ-096**: 원본 파일 저장 (S3 호환 스토리지)
- **REQ-097**: 크롭된 문항 이미지 저장
- **REQ-098**: 생성된 시험지 파일 저장
- **REQ-099**: 파일 접근 권한 관리 (조직 단위)
- **REQ-100**: 파일 삭제 정책 (미사용 파일 자동 삭제, 90일 후)

### 3.3 모니터링 및 알림
- **REQ-101**: 시스템 상태 모니터링 (CPU, 메모리, 디스크)
- **REQ-102**: 작업 큐 모니터링 (대기 중인 작업 수, 처리 시간)
- **REQ-103**: 오류 알림 (Sentry 또는 유사 서비스)
- **REQ-104**: 검수 대기 알림 (운영자에게 이메일/알림)

## 4. 비기능 요구사항

### 4.1 성능
- **REQ-105**: 문항 추출 작업(크롭+OCR): 페이지당 평균 10초 이내
- **REQ-105-A**: 자동 태깅(LLM)은 비동기 처리하며, 배치/재시도를 포함해 평균 1~5분 이내 완료를 목표로 한다(대량 처리 시 큐 대기 포함)
- **REQ-106**: 검색 응답 시간: 1초 이내 (일반적인 쿼리)
- **REQ-107**: 시험지 생성: 5초 이내 (PDF)
- **REQ-108**: 동시 사용자: 100명 이상 지원
- **REQ-109**: 데이터베이스 쿼리 최적화 (인덱스 활용)

### 4.2 확장성
- **REQ-110**: 문항 DB: 10만 개 이상 저장 가능
- **REQ-111**: 파일 스토리지: 무제한 확장 가능 (S3 호환)
- **REQ-112**: 수평 확장 가능한 아키텍처 (마이크로서비스)

### 4.3 가용성
- **REQ-113**: 시스템 가동률: 99% 이상 (월간)
- **REQ-114**: 장애 복구 시간: 1시간 이내
- **REQ-115**: 정기적인 헬스 체크

### 4.4 보안
- **REQ-116**: HTTPS 통신 필수
- **REQ-117**: 비밀번호 암호화 저장 (bcrypt 또는 유사)
- **REQ-118**: SQL 인젝션 방지 (ORM 사용)
- **REQ-119**: XSS 방지 (입력 검증 및 이스케이프)
- **REQ-120**: CSRF 방지 (토큰 기반)
- **REQ-121**: 파일 업로드 검증 (파일 타입, 크기)

### 4.5 사용성
- **REQ-122**: 반응형 웹 디자인 (데스크톱, 태블릿, 모바일)
- **REQ-123**: 접근성 준수 (WCAG 2.1 Level AA)
- **REQ-124**: 다국어 지원 (한국어 우선, 영어 확장 가능)
- **REQ-125**: 사용자 가이드 및 도움말 제공

### 4.6 호환성
- **REQ-126**: 브라우저 지원: Chrome, Firefox, Safari, Edge (최신 2개 버전)
- **REQ-127**: 운영체제: Windows, macOS, Linux (웹 기반)
- **REQ-128 [로드맵]**: HWP 파일 처리: Windows 전용 (별도 서비스)

## 5. 제약사항 및 예외

### 5.1 기술적 제약
- HWP 파일 처리는 Windows 환경에서만 가능 (한컴 오피스 필요)
- OCR 정확도는 이미지 품질에 의존 (흐릿하거나 기울어진 이미지는 정확도 저하)
- LLM 태깅은 완벽하지 않으므로 검수 필수

### 5.2 법적 제약
- 저작권 정보 필수 입력 (법적 책임 회피)
- 개인정보 보호법 준수 (최소 수집 원칙)

### 5.3 운영 제약
- 대량 업로드 시 처리 시간 소요 (비동기 처리)
- 검수 작업은 사람이 수행해야 함 (자동화 불가)
